# ارتقای اختیاری به PN5180 (برد بیشتر) — وضعیت و برنامه

انتخاب تو ارتقا به PN5180 بود. نکته‌ی مهندسی مهم:

کد فعلی RFID (`rfid.cpp`) کاملاً حول کتابخانه‌ی **`Adafruit_PN532`** نوشته شده و ده‌ها
فراخوانی `mifareclassic_*` / `mifareultralight_*` دارد. PN5180 کتابخانه و API کاملاً
متفاوتی دارد (`ATrappmann/PN5180-Library`)، پس ارتقا یعنی **بازنویسی backend خواندن/نوشتن**
— نه یک تغییر چندخطی.

مسیر پیشنهادی (تمیز و کم‌ریسک):
1. اسکچ مستقل `pn5180_reader/` را فلش کن تا سخت‌افزار را تست کنی (خواندن UID روی Serial).
2. سپس یک لایه‌ی نازک backend که پشت همان توابع فعلی بنشیند تا فلوهای منو
   (Card Reader / Clone / Read & Write) دست‌نخورده بمانند و فقط backend عوض شود.

### چرا PN5180 برای کارت آپارتمان لزوماً ۲۰ سانت نمی‌دهد
برد بلندِ PN5180 مخصوص کارت‌های **ISO15693 (vicinity)** است. اگر کارتت
**Mifare (ISO14443)** باشد، برد ~۵–۸ سانت می‌شود (بهتر از PN532 ولی نه ۲۰). اول با
`Card Reader` فعلی نوع کارت را ببین.
